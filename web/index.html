Use Claude Code with your company account

  1. Download the installer

  2. Run it in a terminal

    It installs Claude Code and the AWS CLI if you don't have them, and signs you in with your company account in the browser, once. 

    bash ~/Downloads/install-claude-code.sh

    Downloaded it before? Your browser may have saved this one as install-claude-code (1).sh: run the one you just downloaded, or the old one runs again.

  3. Start Claude Code

    claude

    When your sign-in expires, Claude Code opens the sign-in page again.

Tagging your usage

Any CC_ variable in a Claude Code settings file's env becomes a tag on your usage, to filter and group by here. Put them in a repository's .claude/settings.json (for everyone working in it) or .claude/settings.local.json (just you): 

{ "env": { "CC_PROJECT": "apollo", "CC_TEAM": "payments" } }

For one session, put it on the command line: CC_PROJECT=apollo claude. In a repository that sets its own, the repository's wins, so override it with claude --settings '{"env": {"CC_PROJECT": "apollo"}}'. Without any, your usage has no tags.

Good to know

Models

/model in Claude Code lists the models your admins allow, once for each place requests can go that they allow (Opus 5.5 · EU, Opus 5.5 · Global; with just one, the plain name), and new sessions start on their default. What you pick in /model stays your choice until you run the installer again, which is also how you get the admins' new list when they change it.

What the installer changes

Claude Code and the AWS CLI in ~/.local if you don't have them, two sections in ~/.aws/config, the Bedrock, model, telemetry and tag-check settings in ~/.claude/settings.json (the rest of that file, your own hooks too, stays as it is, except a default model, a /model list or AWS credentials of your own, which would take Claude Code elsewhere), and a small helper in ~/.claude/cc-bedrock/. Telemetry is counts, costs, models and tool names: never your prompts, Claude's answers or your code.

For IT: managed settings

The same settings as managed settings, which people can't override, for /Library/Application Support/ClaudeCode/managed-settings.json (or /etc/claude-code/ on Linux). The README says what else MDM puts in place.
